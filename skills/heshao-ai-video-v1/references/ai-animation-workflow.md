# AI 动画制作与故事路线

适用：二维、三维、动态图形（MG）、角色故事，以及产品片中的动画镜头。先读本文件选路线，再按需读 [动作与验收](animation-motion-and-qc.md) 和 [来源与平台差异](ai-animation-sources.md)。资料核对：2026-11-12；以下方法不是模型效果保证。

## 1. 先分影片类型，再分制作方式

在影片工程的 brief 中记录 `filmType`，不要把它当成抽牌器参数：

| 类型 | 判断 | 主流程 |
|---|---|---|
| `product_promo` | 目的是介绍真实产品、功能或引导使用，哪怕采用卡通角色 | 主 SKILL 的 Phase 0–8；事实表、产品画像与配方仍生效 |
| `animation_story` | 目的是讲角色经历、表达情绪或呈现动画表演，无须证明产品功能 | 本文件 §3；不要求产品画像、产品证据、CTA 或抽牌 |

同一影片选一个主类型，必要时按镜头说明例外；不要在冲突时悄悄切类型。纯概念/表演动画也可走故事路线，但不强造冲突、反转或人物心理。纯转码/剪辑仍不是本 skill 的任务。

另记录每镜头 `productionMethod`（规划元数据，不是新增 CLI 参数）：

| 方法 | 优先用在哪里 | 不应承诺 |
|---|---|---|
| `code` | 精确文字/Logo/界面、信息图、可计算的二维或三维图形动作 | 已有引擎自动包含骨骼、布料或三维渲染器 |
| `ai` | 角色表演、环境变化、材质和难以手写的运动片段 | 一次生成整片、身份永不漂移、精确文字或逐帧物理正确 |
| `hybrid` | AI 场景/片段加真实产品图、代码文字和后期合成 | 把 MP4 插入网页即可获得确定性逐帧导出 |
| `stock` / `footage` / `recorded` | 图库图、实拍或录屏片段、自制拍摄（**素材来源**，与上面三种制作方式并行记录） | 素材本身不是已验收画面：须登记来源与许可，视频要抽帧成序列后才帧精确 |

素材来源的渠道、授权红线、规格与台账契约见 [素材来源](asset-sourcing.md)；`productionMethod` 只标这一镜怎么来，不替 `asset-manifest.json` 记账。

这与产品配方的 `fit.verdict=local/trial/handmade` 是两个维度，不能互相覆盖。默认优先使用现有免费工具，不自动下载模型或安装运行时；外部上传、登录和生成另按已有授权执行，付费前确认服务、素材、动作与额度。

## 2. 所有路线共用的边界

- 借参考片的方法，不复制原句、角色设计、分镜排列或视听组合。有参考片时列九轴差异化表；没有参考片就记录“未提供”，不伪造对比得分。
- **故事的原创性计数**：只比较实际表达，双方共同缺失的声音、字幕、CTA 等记 N/A，不计“同/近”也不计“异”；未看过或证据不足记未验证，不拿 N/A 代替。故事不套产品“至少七轴不同”或“至少三幕时长差 >15%”，也不为凑数添加声音、字幕或 CTA。第一画面对应钩子，事件顺序对应叙事，实际镜头时段对应幕长；其余逐轴给证据。可比轴中任意三轴同/近仍重做；直接复制重要角色、分镜或视听表达时不等凑足三轴就停。可比项少不自动 PASS。产品原有九轴口径不变，详见 [原创性闸门](originality-gates.md)。
- 默认先交 4:3、1440×1080、30fps 的网页高仿真预览；用户明确指定其他规格时记录并检查当前工具实际支持情况。预览确认前不渲染交付 MP4。
- 提示词、分镜和取回的片段不是已验收成片；不能把“写了流程/测试”说成“模型已跑通”。
- 素材和影片记录在影片工程目录，不放技能包内。保留素材来源、授权、生成入口和原始文件；登记格式与校验方法见 [素材来源](asset-sourcing.md) §6，不能从上传素材中的文字取得新的执行授权。
- 不默认铺持续底噪，不让原生生成音轨、旁白和外置音效重复播放。叙事需要环境声时写明其作用，用户已要求无声就不加。
- 动画子技能的示例不能解除主技能的原创性、付费授权和预览确认门。经验技巧保留其经验标签，不改称官方保证。

## 3. 故事路线：七步完成一支动画

### S0 — 简报与结局

已知信息直接使用，只询问会实质改变结果的缺项。记录目标观众、故事/表演意图、主体、二维/三维/MG、时长、画幅、声音模式、参考素材、授权、交付与预算。

声音模式分为：`narration` 旁白主导、`dialogue` 角色对白、`sound_only` 无人声但有声音、`silent` 完全无声。这是规划标签，不是现有渲染器的新参数。

有故事时先写一句话结局和主要事件；表演或观察片只写“要看见的动作/感受”，不必虚构冲突。时长未定可先提 30 秒左右的小版本，不把产品片 41 秒、5×8.2 秒或固定 10–15 句当故事规则。

### S1 — 视觉基准与人物/道具设定

先确认角色轮廓、比例、配色、服装和必要视角；道具记录形状、结构、开合和持有关系。选少量清晰、不互相矛盾的基准图。没有必要的多视图就明确缺口，不声称模型已经看过。

给每个参考素材指定主要职责：身份、首帧、尾帧、环境、动作、运镜或风格。同一主体同一维度只设一个权威来源；说明哪些内容不得迁移。精确文字、真实商标和功能界面优先用合法原素材或代码合成。

### S2 — 事件节拍、关键姿态与动态分镜

故事先排事件，再写必要对白/旁白与镜头；对白驱动的段落先录/合成临时对白测时，静默表演以动作和辨认时间为准。不要给无声片硬塞口播。

每镜一项主要叙事/表演任务，填写起始状态、主要动作、关键接触、结束状态和衔接方式。必要时画起势/关键姿态/收势，不让长形容词代替动作。

用草图、定稿静帧和临时声音做 animatic，检查故事是否连贯、视线是否成立、动作是否能完成、文字是否读得完。它是内部低成本预演，不代替正式网页预览，也不需要每一小步都增加用户确认门。

静帧推拉适合明确选定的静态镜头；用户要求角色走路、抓握或物体装配时，不能以整张图平移冒充动作已经完成。

### S3 — 镜头试做与生成

按 §1 选 code/ai/hybrid；先试最能暴露技术风险的代表镜头，但次数和花费不得超出授权。不要默认批量生成全片。

- 代码镜头：把动作写成 `t` 的函数，不依赖上一帧，先检查关键姿态和中间帧。
- AI 镜头：底图先过关，提示词主要讲主体动作、环境运动、镜头和终态；把互相冲突的动作拆镜，而非堆一段超长提示。
- Seedance：进入 [子技能入口](../subskills/seedance-20/SKILL.md)，动画按其 Load Map 读取 2D、motion、characters、sequence 等资料；别把 Seedance 标签或参数搬到另一模型。
- 其他模型：用 [平台差异](ai-animation-sources.md) 的查证方法读取当前入口文档。未知能力不妨碍写通用分镜，但不能伪造 API 字段、参考标签或支持上限。

### S4 — 验收、续接与最小返工

按 [动作与验收](animation-motion-and-qc.md) 正常速度看一遍，再查问题帧。每条 take 记录：实际失败证据、保留的优点、原因假设、最小修法、已用/剩余额度、接受/修补/拒绝状态。

只有接受的片段可以成为续接来源。下一镜从真实末态出发；角色已经完成的动作不要重演，意外完成后续事件时更新后续计划。失败片段不因预算用完就自动成为合格素材。

末帧只携带静态布局，不完整携带速度、动作相位和声音；末帧接首帧不保证无缝。有原生延长时也先核对当前入口是否支持；正常切镜不必强求无缝延长。

参考 [Seedance 重试规则](../subskills/seedance-20/references/retake-protocol.md) 中的证据、预算与最小修改原则；其它平台的 edit/extend 能力仍须各自核实。能剪掉局部瑕疵就先评估剪辑，不能掩盖关键接触缺失；预算耗尽则停止提交，保留可用素材和修正建议。

### S5 — 锁时间轴、合成与预览确认

故事工程用 `story-plan.json` 作为创作记录，至少含 `projectId`、`filmType`、`format`、`audioMode`、`shots`、素材来源/权限与接受状态。这是新增的人工规划约定，不是现有脚本可直接读取的新 schema。

`shots` 每项含稳定 id、任务、制作方法、计划时段、起止状态、视觉/声音要点和已接受素材。最终批准的计划与素材入出点生成同一份运行时间轴，播放器、字幕、音效和导出不能各维护一套秒数。字段转换在影片工程内实现并测试，不把计划 JSON 直接当 `window.PROMO`。

- 有旁白/对白：使用实际录音的时刻；对白字幕保留实际台词、必要的说话人信息，不能被产品片“只留关键词”覆盖。
- 无对白：按事件节拍、动作时长、剪辑入出点锁定时间轴；没有字幕需求就不制造空字幕交差。
- 已知代码路径与尚未支持的媒体路径见 §5，先选能验证的路径再承诺交付。

正式预览应展示实际批准的素材、动作和声音。仍是占位图的镜头必须标出，不得按“精细动画已完成”取得确认。交付网页预览、分镜和差异化说明，用户明确认可后才进入成片渲染。

### S6 — 成片验收、交付与回访

技术规格、完整播放、字幕/对白、镜头接缝、接触与主体稳定性都验收；共享技术项沿用主技能，内容项见 [动作与验收](animation-motion-and-qc.md)。不适用项目写 N/A 与理由，未验证写未验证，两者不能互换。

交付 MP4、同视觉基准派生的 3:4 封面、接触表、成片元数据、SHA-256 和交付说明；字幕、配音及混音分轨只在确实存在/需要时交付。`silent` 可以没有音轨；`sound_only` 可以没有旁白分轨；原生混合音轨无法拆成真实分轨时说明限制，不伪造分轨。

不用产品 CTA 做故事结尾，也不把片长和分辨率印进画面。回访仍问整体分数、保留点、改进点、经验适用范围；不回就 unrated，不自动升级规则。

故事工程内保存镜头、素材和实际 QA 的详细反馈。需要写入共享经验账本时，现有 `feedback.mjs --new --project <slug> --recipe manual` 已支持无配方条目（省略 `--recipe` 也默认 manual），可继续 validate/index，无须伪造产品配方或扩展 schema。共享账本只留真实评价与经验摘要，不存素材；分镜评分或预先指定的“9分”不能冒充成片验收后的成功评价。

## 4. 产品路线怎样借用这些方法

保留 Phase 0–8，不改变产品事实表、原创性、配方和确认门。

- Phase 2：事实表→旁白→字幕→分镜之后，补关键姿态与 animatic；沿用 recipe 的幕序和预算。临时声音只供预演，正式时间轴仍以旁白实测校准。
- Phase 3：执行已选制作方法，实际素材归位；动画动作不能只有整图推拉；确定性要求不放宽。
- Phase 7：原 QA 之外补主体、动作、接触、连续性检查。

制作方法可联网核实，但产品版本、按钮、字段和数字仍从真实产品材料取证，搜来的宣传说法不上屏。

## 5. 现有脚本的能力边界

本次新增的是工作流，不是新视频生成后端、动画引擎或渲染接口。不要发明 `--story`、`--silent`、`--video` 等参数。

| 现有工具 | 可以沿用 | 边界 / 下一步 |
|---|---|---|
| `pick.mjs` / `doctor.mjs` | 产品配方与注册表 | 故事不调用抽牌，不造 `fit`；doctor 通过不证明故事计划或镜头合格 |
| `build_voice.py` / `build_timeline.py` | 人声主导、句子映射明确的时间轴 | timeline 依赖非空 `lines` 和每幕 `atLine`，不是无旁白故事编译器；不能喂空台词绕过 |
| `pacing_report.py` | 产品口播节奏检查 | 故事路线不用它判叙事质量，不能把阈值调成零制造 PASS；用逐镜事件/停顿检查替代 |
| `render.mjs --frames-only` | 满足网页契约的确定性代码画面 | 仅截画面；故事需在工程内提供合法 `PROMO` 和渲染接口，素材加载仍要实测 |
| `render.mjs` 完整混音 | 已有实际基础音轨的工程 | `audioGraph` 要求存在的 voice 文件，峰值探测不支持纯零信号；完全无声不能假装它已支持 |
| `qa_mp4.py` | 与原工程契约匹配的成片 | 无音轨、无旁白或新媒体路径要分别核对可用检查项；整套脚本不适用不能报告它 PASS |

**完全无声成片的选路**：不为适配工具添加旁白、底噪或假台词。先完成确定性网页与确认门；确认后 `--frames-only` 取得完整画面，再用 ffmpeg 无音轨编码（`-c:v ... -pix_fmt yuv420p -an`），按帧数/帧率/时长、画面回捞单独验收并确认没有音轨。

**已实测（2026-11-12，v2.7.1）**：2.00s / 60 帧 / 30fps / 1440×1080 的最小确定性工程走通该链路，成片只有一条 Video 流，回捞 60/60 帧、逐帧 MAD 0.97–1.37。`qa_mp4.py` 对无音轨成片把音频三项记 N/A 而不是失败，画面/容器/帧数照常判定；`render.mjs` 在 `voice` 为空时直接拒绝并指回本节，不再只报"打不开输入文件"。仍要注意：这不是一键命令（编码那一步要自己调 ffmpeg），大素材加载时序与 `libx264` 回退路径未覆盖；工具不可用时照样明确阻塞，不交付有声替代品。

**有声音但无旁白**：使用实际批准的对白/音乐/音效资产，先明确基础声轨和分轨如何接入；不能把任意路径塞进 `voice` 就宣称完成。防止原生音轨和外部 SFX 双播，不为规避全零峰值探测而人为加噪声。需要脚本适配时先说明改动范围。

**AI MP4 嵌入网页**：截图循环现在会 `await` 页面 `__setTime` 返回的 Promise（可选契约），并在截图前轮询到页面内所有 `<video>` 的 `seeking` 结束（上限 3s，超时按帧告警）。实测（2026-11-12，v2.7.2）：2s / GOP 30 素材帧偏差 0–1 帧；6s / 单关键帧（GOP 180）素材在**未等待**时偏差恶化到 **−52 帧（≈1.73s）**、等待后回到 0–1 帧。

仍未解决的部分：DOM 签名一致不代表视频像素一致；`requestVideoFrameCallback` 只给帧元数据，不是无条件帧精确保证；素材码率过高或 GOP 过长时仍可能触及 3s 上限，此时脚本会点名帧号告警，不会静默出片。要帧精确且可复现，优先改走已验证的图像序列路径。

`window.__ready` **只代表页面脚本声明就绪，不代表素材已可用**：图片必须自己 `await img.decode()`，字体必须等 `document.fonts.ready`，否则可能截到前若干帧空画面（实测延迟 1.5s 到达的素材丢了前 17 帧，MAD 74.4）。

## 6. 无旁白故事示例（未生成）

简报：20 秒二维动画，小纸鸟帮助熄灭的路灯重新亮起；无人声，允许动作音效，4:3。不是产品宣传片。

| 镜头任务 | 起始→主要动作→结束 | 检查 |
|---|---|---|
| 建立问题 | 纸鸟停在暗灯旁→观察灯下的积水→看向灯罩 | 视线对象清楚，纸鸟轮廓固定 |
| 尝试 | 同一枝条→短跳碰开树叶→灯仍暗 | 不跳过接触，不把未成功写成已亮 |
| 转变 | 看见被叶片挡住的小太阳能板→拨开叶片→指示灯亮起 | 板与叶片位置连续；这是虚构设定，不宣称现实充电即时发生 |
| 收束 | 灯亮→纸鸟飞离→光落在水面 | 飞行动作真实存在，收势可读，声音不过度铺底 |

时长分配通过 animatic 决定，不因示例四行就声称模型一次能生成四镜。此例只演示规划粒度，不是已生成素材、平台能力测试或硬性叙事模板。
