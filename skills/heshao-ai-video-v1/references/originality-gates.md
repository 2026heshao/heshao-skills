# 原创性闸门 / Originality Gates

目标：在“参考方法论”和“严禁雷同”之间做可执行的判断。不要用“参考风格”当雷同理由。

## 1. 九轴矩阵

逐轴对比参考片与新片，标 `同 / 近 / 异`。**任意 3 个轴为“同/近”，重做。**

| # | 轴 | 要问的问题 | 合格标准 |
|---|---|---|---|
| 1 | 钩子 | 第一句/第一画面是否在复用参考片的钩子类型与关键词？ | 钩子类型或对象至少换一个；原句不复用 |
| 2 | 叙事顺序 | 卖点顺序是否与参考片一致？ | 至少改变一次主顺序（如搜索→安装 改为 盘点→减重） |
| 3 | 镜头语法 | 是否同样长镜头/单一相机/固定机位？ | 换一种：固定台+硬切 / 手持 / 俯拍 / 微距 / 分屏 |
| 4 | 幕长组合 | 每幕时长是否接近参考片？ | 至少 3 幕的时长差 >15% |
| 5 | 转场 | 是否同样光扫/半调/闪白/遮罩？ | 换一套材质：机械快门/纸张/扫描/翻页 |
| 6 | 字幕系统 | 位置、出现方式、关键词策略是否同样？ | 位置或出现方式至少换一个 |
| 7 | 视觉母题 | 配色、材质、字体、记忆点是否同气质？ | 换世界：暖金属 → 骨白纸单/钢箱；或蓝图/塔台/档案 |
| 8 | 声音排列 | 音效名单、密度、卡点是否同样？ | 换音效材质；底拍/转场音至少换一类 |
| 9 | CTA | 动词与句式是否复用？ | 换价值句/动作顺序（“一条命令装好 / 完全退出再打开” vs “装得明白，也用得回来 / 一行命令，搬进 DSH”） |

> 机器字段里的 `originality-8-axis` 是历史兼容标签；实际按本表 **9 轴** 执行（第 4 轴幕长、第 9 轴 CTA 都要过）。

## 2. 红色信号

看到以下任意一条，先停下来改：

- 第一句和参考片共享 2 个以上关键词（如“四个地方 / 四个市场 / 一个搜索框”）。
- 幕数与幕长几乎一样（如 5 幕 8/10/14/9/4.6）。
- 参考片不硬切，你也用长镜头；参考片硬切，你也硬切——**先问为什么**。
- 字幕都在屏幕中下、都用逐字点亮、都只留关键词。
- 配色是参考片的互补色，但材质、字体、构图、光效仍是同一套。
- 音效名单是参考片的子集，卡点位置也一致。
- 你自己上一支片子的皮肤被直接套用（暖纸/暖金/石墨/冰蓝），只换了文案。

## 3. 改写策略

不要“换颜色”，要换**语法**。可行的手法：

1. **反转镜头语法**：长镜头 → 固定台硬切；横移 → 俯拍；推近 → 拉远；连续世界 → 分幕换台。
2. **换叙事容器**：入口焦虑 → 记忆/盘点；功能列表 → 审计；装配 → 救援；一天 → 倒计时。
3. **换叙述者**：旁白 → 现场收音/字幕卡/物件视角；第二人称 → 第一人称；现在时 → 回溯。
4. **换时间方向**：从结果倒推（先看乱局，再回到入口）。
5. **换媒介**：屏幕 UI → 纸单/钢箱/档案/蓝图/塔台；数字 → 印章/条码/标签。
6. **换声音材质**：合成器 riser → 机械继电器/纸张/伺服/扫描；BGM → 纯动作音。
7. **换字幕角色**：关键词贴纸 → 左下入库标签/页脚注释/物件标签。
8. **换 CTA 语法**：命令式 → 价值句 + 具体动作；或反过来。

## 4. Filled example：depot vs kinetic

| 轴 | 参考片 kinetic | 新片 depot | 判定 |
|---|---|---|---|
| 钩子 | 四个动作并列 + 四个地方 | 第二人称提问 + 装完未被调用 | 异 |
| 叙事顺序 | 入口散 → 面板 → 搜索/安装 → 广度 → 命令 | 建账 → 翻账 → 减重 → 点名 → 入库 | 异 |
| 镜头语法 | 单一光带、长镜头、不硬切 | 固定盘点台、百叶快门硬切 | 异 |
| 幕长 | 8.57/10.65/13.99/8.72/4.60 | 6.05/7.67/7.13/6.99/8.62/8.48 | 异 |
| 转场 | 暖光扫/半调擦除/闪白 | 百叶快门/机械闸门 | 异 |
| 字幕 | 中下关键词贴纸 + 逐字点亮 | 左下入库标签 + 打印式揭示 + 独立关键词块 | 异 |
| 视觉母题 | 蜂蜜金金属字/体积光/光带/取景框 | 骨白纸单/条码/钢箱/红章/夜班盘点台 | 异 |
| 声音 | riser/whoosh/shimmer，16 文件 58 事件 | 13 个自产机械音 + 0.6s 纯低频底拍 | 异 |
| CTA | 一条命令装好，完全退出再打开 | 装得明白，也用得回来；一行命令，搬进 DSH | 异 |

结论：9 轴全异，可以提交。注意：这不是“必须 9 轴全异”的模板；3 轴以上相同才需要重做。

## 5. 自检流程

1. 把参考片与新片的文案并排，逐句标“同/近/异”。
2. 把分镜表并排，标幕数、幕长、镜头任务。
3. 把转场、字幕、视觉母题、音效名单各列一列。
4. 让一个没参与创作的人看 10 秒，问“这像不像那支片？”如果他说“像”，找出像的轴。
5. 写出**差异化说明**，至少覆盖：文案、分镜、转场、字幕、视觉、节奏、音效、CTA。
6. 如果无法保证不雷同，停止推进并说明原因；不要用“参考风格”作为理由。

## 6. 交付话术

> 只借鉴了「强钩子、快节奏、高信息密度、强卡点」的策略；具体文案、分镜顺序、幕长、转场、字幕动效、视觉母题与音效排列均已重做。逐项对照见差异化表；未发现需要重做的雷同项。

如果确实有某轴接近，主动标出来并解释为什么保留（例如产品类目词无法替换），不要假装全异。

## 7. v2 系统层防线

v2 不靠临场自觉，靠牌组和兼容矩阵：

- 参考片的具体表达在 `decks/*.json` 里标 `banned: true`（暖光扫、半调、闪白、中下贴纸、riser/whoosh、四个地方钩子），`pick.mjs` 默认永不选。
- `compatibility.json` 只允许世界与转场/字幕/声音/节奏的合法组合，避免“暖纸 + 霓虹紫”这类坏搭配。
- `--base` 时最多改 2 个轴；改 world 后不兼容的轴会自动重抽并记入 `forcedAxes`。
- 默认排除最近 3 份 recipe 的 world/hook，减少重复。
- 每次抽完先跑 `--validate`，再做差异化矩阵；系统不让抽的卡，不要手改 recipe 绕过。
