# 评分卡 / Scorecard

每个候选在锁定前盲评。去掉作者/方案名，只看结果。0–10 分；任何一项低于 6 分就不进入下一轮。

| 项 | 问题 | 10 分标准 | 失败信号 |
|---|---|---|---|
| 钩子 | 第一句/第一画面是否让人对号入座？ | 3 秒内知道“这说的是我” | 需要解释才懂 |
| 缩略图 | 在 270×360 下能否读出主张？ | 主标题 + 一个强符号 | 字太小、元素打架 |
| 事实 | 每个上屏内容是否有出处？ | 事实表逐条可指回 | 编数字、字段跨界面 |
| 节奏 | 45 秒内是否有密—疏—密？ | 单幕一个动作链，关键点有 hold | 平均用力、连续硬切 |
| 原创 | 与参考片至少 7 个轴不同（最多 2 个同/近）？ | 9 轴全异或差异可解释 | 同钩子/同分镜/同字幕 |
| 音频 | 旁白清晰、音效不压人、无削顶？ | 峰值留 1–3 dB，0 削顶 | 底噪、齿音、click 床 |
| 工程 | 预览可 seek、成片帧对齐？ | 纯函数 seek 一致、A/V 偏移 ≤1 帧 | CSS 动画混入、音画错位 |

## 使用方式

1. 一次生成 2–3 个候选，编号 A/B/C，不写方案名。
2. 先看缩略图 3 秒，再看完整预览；先记第一反应，再逐项打分。
3. 任何一项低于 6：直接淘汰，不做“整体还不错”的妥协。
4. 事实项必须是 10；原创项必须 ≥8；否则重做。
5. 锁定后把分数写进 recipe 的 `score`，并写一句 `notes`：为什么选它。
6. 成片交付后按 `references/feedback-loop.md` 回访；用户对成片的评分写 `experiences/`，不要直接改权重/牌组。

## 回填

有播放/完播/互动数据时，在 recipe 里加：

```json
"performance": { "views": 0, "retention3s": 0, "completion": 0, "saves": 0, "source": "douyin" }
```

只把**相对同账号/同类型**的表现用于调权重，不要拿绝对值跨账号比较。

## 杀单条件

- 需要解释才懂的钩子；
- 缩略图读不出主张；
- 上屏数字/状态没有出处；
- 与参考片 3 个以上轴相同；
- 旁白有可听出的齿音/click 底噪；
- 成片削顶或音画偏移 >1 帧；
- 一次改了 4 个以上变量，无法归因。
