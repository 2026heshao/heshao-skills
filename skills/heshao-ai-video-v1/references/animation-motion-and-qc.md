# 动画动作设计与镜头验收

适用于产品动画与故事动画；先按 [制作流程](ai-animation-workflow.md) 定路线。动画原理来自 Adobe 等专业资料，向 AI 制作的迁移是工作建议，不是生成模型的确定性承诺。出处见 [来源登记](ai-animation-sources.md)。

## 1. 先问这一镜让观众看懂什么

每镜头填一句“观众看到主体做了什么，状态发生什么变化”。先让构图、明暗、动作和声音突出这一件事，再考虑装饰。

- 背景动、字幕跳、镜头转、主体表演不要同时争抢焦点。
- 一个主要动作不等于其它人冻结；配角可以有不抢戏的自然小动作。
- 推进镜头不是角色运动；需要走路、抓握、转身时必须检查主体自身确实完成动作。
- 技术示意可以平直、匀速；故事也可以停格和留白。不要把“高级”翻译成统一的慢镜、浅景深和大量形容词。

## 2. 动作卡：先姿态，再过渡

按需要填写，简单 UI 点击反馈不用被迫加上复杂表演：

| 项 | 写法示例 / 要检查的事 |
|---|---|
| 起始状态 | 谁在哪里，身体/道具朝向，谁持有什么 |
| 预备 | 发力、瞄准、重心准备，或明确无需预备 |
| 主动作 | 可见动词：转头、推开、落下、旋入；不是“变得高级” |
| 接触/改变 | 哪只手碰哪个位置，碰到后什么改变；没有接触则 N/A |
| 收势/跟随 | 主体停下后哪些附属部分继续运动，或机械直接停止 |
| 结束状态 | 画面里能看见的结果，下一镜能接什么 |
| 观看任务 | 观众应理解的信息，是否需要留出阅读/辨认时间 |

复杂接触先简化参与对象与动作链；必要时拆镜或改机位。不要靠甩镜、强模糊掩盖必须可见的关键动作。

## 3. 按风格选择动画原理

| 原理 | 用法 | 反例 / 边界 |
|---|---|---|
| Staging 视觉组织 | 用构图与运动主次让观众找到重点 | 所有元素一起动反而看不清 |
| Anticipation 预备 | 让跳跃、发力、转向能被预期 | 每次按钮反馈都蓄力会拖慢交互 |
| Pose-to-pose 关键姿态 | 先定关键动作与落点，再处理过渡 | AI 首尾帧不保证中间动作按设计实现 |
| Timing / spacing 时长与间距 | 分别设计动作多久完成、每段走多远 | 一律加慢不等于有重量 |
| Slow in/out 缓入缓出 | 控制启动和停止的节奏 | 匀速导轨、机械步进或刻意跳变不必强加缓动 |
| Arcs 弧线 | 角色头、手、重心移动可沿合理路径 | 装配件沿直线运动也完全成立 |
| Follow-through 跟随 | 身体停后衣角/毛发仍在收势 | 金属壳体不应无故软化或弹跳 |
| Squash/stretch 挤压伸展 | 用于授权的卡通表现，注意体积与结构读感 | 精密产品、真实包装不要因此变形 |

代码动画可以直接设计时间函数；AI 生成描述这些可见结果，再逐镜检查，不能把关键帧或物理术语当保证。

二维可使用分层、背景滚动、多平面视差、停格、拖影、冲击帧、线条抖动和色块阴影。三维要注意体积、遮挡、接触、材质与光的关系。混合风格需明确哪些维度融合，而不是把所有术语塞进提示词。

Seedance 的 [二维动画语法](../subskills/seedance-20/references/2d-anime-grammar.md) 可按其经验标签使用；其中避免摄影词汇等建议不升级为所有模型/所有混合风格的禁令。动画 on twos 等提示不是帧级控制接口，也不等于必须把交付帧率改成 12fps；保留停格节奏时不要默认做光流补帧把风格抹掉。

## 4. 连续性：检查状态，不只看脸

在镜头卡记录角色身份、服装、产品轮廓、颜色、尺寸关系、持物手、开合、视线、屏幕方向、机位侧、光线和声音状态。不是每项都必须锁死；变化须有叙事或转场理由。

1. 建立简明空间关系，必要时画俯视图或运动箭头。
2. 检查视线匹配：人物看向哪里，下一镜是否给了合理对象。
3. 跨切点检查动作阶段：伸手不能重复开始，抓到物体前不能先出现“已经拿走”。
4. 新位置需要合理动作或剪辑交代；不要把无法解释的瞬移称为自然省略。
5. 越轴、跳切、空间重置可以是明确的表现手法，不一概禁用。
6. 用接受片段的实际末态更新下一镜，不让失败片段成为连续性基准。

## 5. 两遍观看加定点复核

### 第一遍：正常速度

判断任务是否看懂、节奏是否合适、重量和情绪是否成立、注意力是否集中。先完整播放，不能只看接触表或停帧。

故事路线逐镜记录 `镜头任务 / 实际事件 / 有意停顿 / 是否读懂 / 判定与理由`。旁白占比不是故事质量指标；有意留白应有表达作用，毫无变化又无阅读/情绪任务的空等仍要修。

### 第二遍：风险处逐帧

至少覆盖各镜首/中/尾、接触前后、身份转面、遮挡后重现和剪辑接缝。短镜头的固定三帧仍可能漏掉瞬时瑕疵，发现问题时扩大检查窗口。

- **结构**：脸、四肢、产品轮廓、标签、道具数量是否非预期变化。
- **接触**：脚应着地时是否滑动，手是否抓空，物体是否穿入表面，接触阴影是否跳变。先区分运镜导致的屏幕位移与对象相对接触面的滑动。
- **运动**：动作是否完成，运动方向、加速度和姿态是否突跳；停格/拖影等有意风格单独声明。
- **衔接**：道具持有者、光线、朝向和运动相位是否无解释变化；动作是否重复或漏掉关键步骤。
- **画面**：边缘抖动、纹理游走、局部闪烁、字幕越界/遮挡、意外裁切。
- **声音**：有音轨才检查对白、口型、落点、杂音和重复混音；完全无声则确认没有意外音轨。

自动图像相似度和 DOM 签名只能辅助定位，不能证明动作含义正确、角色没变脸或真实视频帧已解码。

## 6. 验收判定与最小修复

以下是制作验收约定，不是平台指标或凭空设定的成功率：

| 判定 | 条件 | 下一步 |
|---|---|---|
| 接受 | 任务完成，必要身份/结构/接触与连续性通过 | 记录实际起止状态与允许偏差 |
| 局部后期 | 可通过剪辑、文字叠加、混音等保住镜头任务 | 先验证修补没有遮掉关键动作或破坏节奏 |
| 重写 / 重试 | 有明确、可检验的改进假设且有剩余授权 | 尽量只改一个变量，记录其它设置；不保证修复成功 |
| 停止 / 换方案 | 预算耗尽、能力不支持或收益很小 | 不继续提交；给出可用素材及替代方案的实际代价 |

硬失败包括：用户要求的关键动作未发生、重要身份/产品结构变了、必要接触缺失、无法解释的状态断裂、素材或使用权不符合要求。只修颜色不能抵消动作没完成。

重试日志最低字段：`镜头/take · 失败时间点 · 保留部分 · 原因假设 · 计划改动 · 固定设置 · 授权剩余额度 · 判定`。同 seed 不构成严格对照实验，不根据一次改善宣称已找出因果。

若统计效率，记录真实花费、实际尝试数和被接受的有效片段长度，并说明样本数；没有实测就不编成功率或节省比例。

## 7. 成片技术检查不能省

按实际交付格式核对画幅、帧率、总帧数与时长，检查全部接缝和动作风险点，保留接触表与来源记录。使用主渲染路径时仍做顺序渲染与直接 seek 比较、成片解码回捞。

产品片沿用原语音节奏和 QA；故事的 N/A 仅覆盖确实不存在的项目（如 silent 无音频削顶检查、无产品无需产品 fit）。不支持的功能或未运行的检查必须记“未验证/阻塞”，不能记 N/A 或 PASS。

有声音时检查音轨覆盖、实际削顶、对白可懂、必要口型同步；有明确事件卡点时按主流程检查对齐。完全无声时验证无音轨，不编音频峰值或音画偏移数据。

脚本返回零只证明它实现的检查通过。现有 `pacing_report.py` 不判断故事表现；现有 `qa_mp4.py` 不自动覆盖所有新合成方式。说明哪些是机器检查、哪些是人工观看、哪些尚未验证。
