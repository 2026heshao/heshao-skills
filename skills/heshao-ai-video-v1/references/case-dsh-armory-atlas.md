## 3. 世界与配方：星图台为什么成立

配方 picks：

```json
"world": "atlas",
"hook": "countdown",
"transition": "eclipse-wipe",
"caption": "plate-header",
"sound": "celestial",
"rhythm": "rescue"
```

推导链：

- 产品名“军械库” → 上一支已经用过夜班盘点台；同产品第二支不能换色复刻。
- 用户动作“装了很多、找不回、叫不出” → 需要一张“很多点也能读”的图版。
- 情绪“失控/遗忘” → 深空、刻度、暗星；不是热闹的科技 HUD。
- 记忆点：黄铜轨道、日食擦圆、左上图版题、暗星圈。

星图台的 `risk: medium` 是真实的：`bestFor` 与夜班盘点台都覆盖“工具库/技能管理”。本片能过闸门，不是因为“星图更酷”，而是因为**具体语法换了**：

- 叙事：失联 → 星图 → 来路 → 暗星 → 牵引 → 落版；
- 镜头：单一星图台拉远/推进 + 日食擦除，不是固定盘点台 + 百叶快门；
- 字幕：左上衬线图版题 + 等宽索引，不是左下骨白入库标签；
- 声音：玻璃泛音/黄铜轻击/气声，无连续底拍，不是机械继电器 + 0.6s 底拍；
- 幕长：6.72 / 8.92 / 5.42 / 7.53 / 10.09 / 8.30，其中 3 幕与参考片差 >15%。

**结论：世界可以复用“能力地图”的需求，但表达必须整套换掉；同产品第二支片尤其要先过幕长这一轴。**

## 4. 文案合同：星图是看法，不是功能

### 4.1 出过的问题

第一版口播/大标题是产品定义句：

- “大肥鱼军械库，把散落的能力**连成一张星图**。”
- 首屏大标题：“把散落的能力 / **连成一张星图**”
- “**星图**不只记名字，也记来路。”
- 片尾：“重启 DSH，**星图就亮**。”

产品里搜不到“星图”。观众会期待一个装完就出现的星图界面，打开却是面板、市场、账本——这是实打实的预期落差。用户原话：“如果直接这样宣传反而可能会引起用户的不满。”

### 4.2 修法

保留视觉世界，只把“产品是什么”交回真实界面。改法不是换世界，而是降级比喻：

| 位置 | 改后 |
|---|---|
| 产品第一次出场 | 如果把大肥鱼军械库**比作**星图，能力就有了坐标。 |
| 首屏大标题 | 把军械库**比作**星图 / 能力就有坐标 |
| 字幕关键词 | 星图**视角** |
| 中段 | 星图是**看法**，**账本**记来路。 |
| 片尾 | 安装就这一句；重启 DSH，**面板里**就亮。 |
| 落版脚注 | 星图为视觉比喻 · 实际界面在面板 / 市场 / 技能账本 |

结果：星图只以两种身份出现——一种看问题的视角，一套视觉语言；产品仍然是面板、市场、技能账本。封面沿用同一合同。

### 4.3 可迁移规则：比喻合同

只要视觉世界是产品里不存在的东西（星图、雷达、蓝图、卷宗），先写四句话：

1. 第一次出现必须用“**比作 / 像 / 是看法**”，不能是“把 X 连成 Y”。
2. 中段至少一句把话题交回**真实界面名词**（面板、市场、账本、菜单）。
3. 落版和封面各留一处**小字脚注**，写清实际入口。
4. 产品里搜不到这个名词，就不要用“实现/生成/点亮”这类动词。

自检：在代码/README 里搜这个名词。搜不到，它就是比喻，不是功能。

## 6. 问题与修复（按发生顺序）

### 6.1 图版编号 01–06 vs 底栏 00–05

- 症状：左上图版写 `PLATE 01 / 06`，底栏却写 `00 / LOST SIGNAL`。
- 根因：时间轴生成器里 `hud` 用了 0-based 索引，图版用了 1-based。
- 修法：`build_timeline.py` 的 `hud` 改成 `i+1`，图版/底栏/章节共用同一编号；`shot.mjs` 抽 0.8s 与 46.4s 核对。
- 规则：**HUD 编号从 01 开始，只有一个生成源。**

### 6.2 片尾光圈收得太早，压住 CTA

- 症状：光圈 45.05s 开始收，最后一句旁白到 45.88s，安装命令被压黑。
- 修法：光圈改到 45.80s 起收（前 0.1s 仍接近全开，不压字）；命令保持完整可读 ≥1.2s；淡出 46.36–46.98s。
- 规则：**落版先保旁白和命令可读，再收光圈/淡出。** 任何“好看的转场”都不能吃掉 CTA。

### 6.3 单句 TTS 气口被听成“配音有杂音”

这是本轮最有价值的音频排查：

- 症状：用户说“配音有轻微的杂音”，但全片不是持续沙沙。
- 量法：按句切 20ms 帧，算每句的 p10/p5 与深气口；发现第 10 句（“点一次，三条指令按顺序落下”）p10 `-56.9 dB`、p5 `-62.6 dB`，其他句大多 `-64 ~ -72 dB`。它比全片高约 10 dB，是**单句气口**，不是全片底噪。
- 先试 `afftdn`：对这类气口无效；谱减还会引入音乐噪声。
- 再试 −46 dB 温和门限：受包络 release 与气口电平影响，p5 只降 1.4 dB，且可能切字尾；放弃。
- 最终：把同一句的逗号换成分号（`点一次；三条指令按顺序落下。`），换出一个更干净的 TTS take：p10 `-56.9 → -64.7 dB`，p5 `-62.6 → -69.0 dB`，气口不再离群；语音 RMS/真峰值不变，时长只多 0.1s。
- 连带：三条指令的视觉卡点后移 0.3s，与新气口对齐。
- 规则：**先按句量，找离群句；单句异常先换 take（标点/停顿变体），不要整片降噪或加门限。** 如果必须门限，放在低通之后，release 不要太慢；但优先从源头换 take。

### 6.4 制作参数被带进画面

- 症状：S01 副行与底栏右侧印着 `4:3 · 1440×1080 / 30FPS`；预览里像制作 slate，成片里是杂讯。
- 修法：S01 副行改 `CAPABILITY ATLAS · 星图是看法`；底栏右改 `v2.4.7 · MIT`；落版版本行只留 `v2.4.7 · MIT`。
- 规则：**画幅/分辨率/帧率只放抽屉、README 和交付说明，不进画面。** 画面脚注放品牌、版本、比喻声明。

### 6.5 封面第一版的星点与“日食”碰撞

- 症状：亮星压在右上角 `3:4 · 1080×1440` 上；巨大日食圆的边缘穿过“技能 27”“专家 08”标签。
- 修法：去掉日食填充，只留轨道；星点生成从 `y=110` 开始，避开顶栏文字；亮十字星移到空白区。
- 规则：**封面先排文字安全区，再撒星点/装饰；装饰不能穿过标签。**

### 6.6 配方漂移与重复文件

- `recipes/dsh-armory-atlas-20261104a.json` 是本片实际配方（atlas/countdown/eclipse-wipe/plate-header/celestial/rescue）。
- `recipes/dsh-armory-atlas-atlas-20261104a.json` 是修复前默认文件名重复的产物，picks 是 tower/contrast/scan-wipe，**不是本片配方**；已在该文件 notes 标记 DEPRECATED。
- 规则：**配方名与实际 picks 必须对得上；重复命名产物不要留在 recipes/ 里冒充配方。**

## 9. 可迁移清单

1. **同产品第二支片**：把上一支当工程基线，不当皮肤；先改世界与叙事，再谈文案。
2. **视觉比喻**：产品里没有的名词，一律先写“比作/看法”，中段交回真实界面，落版/封面加脚注。
3. **幕长**：不要只看总时长；逐幕对比，至少 3 幕差 >15% 才算换骨。
4. **配音杂音**：按句量 p10/p5；单句异常先换 take；不要整片 `afftdn`/门限。
5. **编号**：图版、底栏、章节共用 1-based 生成源。
6. **落版**：最后一句和命令完整可读后，再收光圈/淡出。
7. **上屏**：制作参数不进画面；脚注放品牌/版本/比喻声明。
8. **配方漂移**：实际幕结构变化回写 recipe.notes 与差异化矩阵；删除/标记重复命名的旧 recipe。
9. **封面**：先排文字安全区，再撒装饰；装饰不能穿字。
